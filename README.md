## 目录与归属

- `client/`：原 Debug_LAN 命令行接入工具、配置样本和测试；保持零 pip 运行依赖。
- `server/`：Linux 远程服务、RTT 采集及相关页面；不在 Windows 开发机上运行该服务。
- `embedded_helper`：独立 C# 桌面客户端，通过约定接口与服务端交互。

`client/` 与 `server/` 不互相 import。当前 [客户端说明](client/README.md) 和 [服务端说明](server/README.md) 保留来源项目的使用方式；其中的旧路径、仓库名和部署步骤尚未适配。

## 版本机制方向

服务端借鉴 embedded_helper 的版本机制：以 `server/VERSION` 作为服务端 SemVer 唯一来源，由统一版本更新入口修改，运行时 `/status` 读取同一来源，变更说明记录在服务端 CHANGELOG 中。

参考基线为 embedded_helper `0.2.1-alpha.2`，提交 `2ed82b73b7f6215b13670b22b24a4455eef8bb02`；参考内容包括 `VERSION`、`scripts/bump_version.py` 和概要设计第 10.4 节。

服务端、命令行客户端和 embedded_helper 的产品版本独立，不跨组件强行对齐。跨端兼容使用单调整数 `contractVersion`，索引行结构使用 `sv`；已有历史日志按 contract 0 只读处理。

本复制基线尚未新增 `server/VERSION`、版本更新脚本、`/status` 或 CHANGELOG。具体接入和 Harness 改造在首个源码提交之后讨论；服务端不引入发布门，版本更新不自动创建 tag 或 Release。

## 后续需求边界

- RTT 为日志主通道，串口只承担高门槛告警，38400 链路不作为日志通道。
- 远程由 r1 唯一采集和保存，本地由 helper 采集并必须落盘；远程 helper 不落盘，两端使用同一日志 schema。
- 标注只由 helper 经 API 写入数据所有者，r1 网页只读；禁止自动双写，只允许明确的人工 promote。
- 数据分为 `raw/`、`index/index.jsonl`、`run/`；已封口原始轮次不可变，索引仅追加且每行带 `sv`，板级日志与程序日志不放在同一目录。
- 谁删除数据、谁终止进程、谁持有探针以及谁判定版本兼容，须先形成明确需求，再实现对应行为。
- 不分发未获书面授权的 SEGGER CLI 或整套安装包，后续改为官网下载引导；USB 驱动只检测并指路。
- 板侧主机可见契约目前仍位于来源仓库被忽略的 `Docs/`，尚未入库；其入库是建立单源引用与兼容判定的先决条件。
